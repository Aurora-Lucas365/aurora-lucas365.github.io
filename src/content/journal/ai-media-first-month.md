这是一张**待执行的选题清单**，不是已发布作品目录。我的原则是先确认问题真实存在、自己能复现，再录屏讲解。一个视频只回答一个问题：开头呈现报错或成品，接着说明适用系统与前提，演示一到三个关键动作，最后重新运行验证。不能解决时，改成排查复盘，不硬凑成功案例。

## 第一批 12 个题目

| 周次 | 要展示的问题 | 观众应带走什么 |
| --- | --- | --- |
| 1 | AI 工具打不开，先别重装 | 区分安装、登录和服务可用性的问题 |
| 1 | Obsidian 笔记怎样变成可更新的网站 | 展示公开筛选、同步与隐私边界 |
| 1 | AI 给的命令能直接复制吗 | 检查来源、作用路径与回退办法 |
| 2 | Windows 提示找不到文件 | 核对下载目录、版本和权限 |
| 2 | 怎样把报错讲给 AI 听 | 交代系统、复现步骤、截图和已尝试方法 |
| 2 | 给家人做的网页为什么断网也能用 | 看懂离线能力与本机数据边界 |
| 3 | 普通聊天和工作流有什么差别 | 用同一重复任务比较输入、处理和人工验收 |
| 3 | 登录或注册卡住，先查什么 | 查官方支持范围、账号状态与服务公告 |
| 3 | 一项重复整理工作能节省多少时间 | 同时记录工具耗时与人工复核耗时 |
| 4 | AI 做网页容易漏掉什么 | 手机适配、可用链接与资料归属 |
| 4 | 一次失败排障复盘 | 公开判断依据，不公开他人信息 |
| 4 | 评论里最高频的一个问题 | 让真实问题决定下一条内容 |

这些是测试题目，发布前根据素材和评论调整。对 GitHub 项目或新工具，先核对官方文档、版本、许可证和实际运行结果；不把别人的演示当成自己的成果。教程尽量标清 Windows 或 Mac 的适用条件，无法验证的系统不做肯定式结论。

## 制作与分发

先以 Windows 录屏、本人配音和剪映桌面版建立固定模板；字幕手动校对技术词，必要时局部放大，但不能剪掉决定成败的步骤。不露脸没关系，清楚的解释和可核验的结果才是辨识度。前四条先用现有设备完成，再决定要不要买麦克风或测试 CapCut 的双语制作。

大号发布完整实操；小号只补学习过程、失败点或幕后。B 站和公众号适合放更长的说明，暂不要求每个平台都独立生产内容。评论区先给排查方向、询问用户遇到的真实障碍，不复制同一段招揽话术。若内容含明显 AI 生成的拟真人物、声音或画面，发布时按平台现行标识要求处理。

## 帮助别人时，什么能做、什么要停

公开答疑可以给一两个判断和官方资料。需要逐项排查、远程操作或按结果交付时，先确认范围、时间、费用与验收，不把「以后随时问我」当成无限期售后承诺。客户可以选择屏幕共享指导，而不必交出电脑控制权。

远程协助前确认系统版本、设备归属和授权，提醒关闭敏感窗口并备份。密码、验证码、付款和注册由本人输入；遇到删除文件、改变权限等难以回退的操作，暂停并让设备主人决定。结束时由对方自己复现结果，撤销临时授权，留下简短的处理记录。对不熟悉的 Mac 环境，先练习与验证，不拿客户机器当训练场。
